# LoRA Studio: проверка удобства против трёх исходных расширений

Дата: 2026-11-05. Это результат проверки, а не заявление о готовом новом UI.

Дополнительный проход в тот же день: 55 браузерных проверок повторно PASS;
в узкой области подтверждена прокрутка до действий, после кнопки Cancel фокус
теряется на BODY. Добавить единый возврат фокуса после закрытия. Кроме UX,
обнаружены runtime/API проблемы; актуальная общая очередь — в
`СВОДНЫЙ_АУДИТ_UI_LORA_VAE_EMBEDDINGS_2026-11-05.md`. Исправление API auth
и bias/Embedding предшествует заявлению о готовом релизе, UI-работы не отменяются.

## Главный вывод

Studio нельзя пока считать полноценной заменой удобства исходных расширений.
Перенос параметров в native runtime и сохранение пресетов не заменяют быстрые
сценарии редактирования. Часть возможностей перенесена, но требует больше действий;
часть отсутствует. Новая архитектура расчёта сама по себе эти проблемы не решит.

## Что действительно проверено

- Код текущей Studio и исходников из `extensions/check`: Weight Helper,
  LoRA Block Weight, LoRA Control. Оригиналы не перемещались и не активировались.
- Текущая Studio запущена в настоящем браузере на локальном
  `test/lora_studio_fixture.html`. Просмотрены Quick tune, Advanced controls,
  Classic 17-block layout и взаимодействие с черновиком.
- В браузере прошли **55 проверок**: 51 сценарий состояния/событий и четыре
  проверки контраста (светлая/тёмная тема, с токенами темы и без них).
- Отдельно Node: 17 тестов, включая 51 событие/проверку DOM. Это НЕ ещё
  51 независимая интеграционная проверка: сценарии общие с браузерным стендом.

Это статический стенд с подменёнными API, не запущенный Gradio/WebUI.
Ресурс webui-assets/css/sourcesanspro.css на статическом сервере отсутствовал;
использован fallback-шрифт. Точное совпадение размеров с рабочим WebUI не заявляется.
Исходные расширения изучались по коду, а не одновременно в рабочей генерации.
Старый белый фон полей на этом стенде не воспроизведён. Проверка других тем,
масштабов и конфликтов CSS в установленном WebUI остаётся обязательной.

## Три основных недостающих удобства

| Действие | Исходный Weight Helper | Текущая Studio | Решение |
|---|---|---|---|
| Быстро подобрать вклад блоков | Ползунок, число и переключатель блока в том же компактном редакторе | Full Studio → Advanced → профиль → прокрутка; сами блоки — текстовые поля | Блоки в Quick tune: ползунок + точное число + временное выключение с восстановлением |
| Вернуться к удачному варианту | История назад/вперёд, закрепление варианта | Библиотека пресетов/избранное не являются историей текущих правок | История черновика + закреплённые варианты, отдельная от библиотеки |
| Настроить LoRA, не теряя prompt и Apply | Перетаскиваемый компактный редактор, дополнительные параметры раскрываются | Большой блок пресетов сверху; на проверенном размере окна Apply ниже видимой области popup, нужна внутренняя прокрутка; drag отсутствует | Короткая верхняя панель, сворачиваемые пресеты, постоянно доступные Apply/Cancel, перенос/ограничение окна по экрану |

### Проверяемые места в исходниках

- Weight Helper: `src/components/sections/common-section.ts` — range + number
  + checkbox, настраиваемый шаг; `lbw-section.ts` — те же контролы для блоков.
- `header-section.ts` — перемещение окна, история и закрепление;
  `src/shared/manager/history-manager.ts` — хранение истории параметров по LoRA.
- `preview-section.ts` — изображение, metadata, действия с trigger words;
  `scripts/weight_helper.py` — UI scale, диапазоны/шаги, размер/позиция preview.
- Studio: `javascript/loraStudioView.js`, `renderExactBlockEditor` — текстовые
  поля блоков; `renderQuickTune` — порядок секций, кнопки в конце содержимого.

## Что ещё не равно исходникам

**Контекст LoRA.** У Weight Helper есть изображение-превью в редакторе, действия
с metadata/описанием и вставка trigger words в positive/negative prompt.
У Studio уже есть информация, подсказки trigger words и сохранённые настройки;
нельзя говорить, что ничего этого нет. Но Quick tune не даёт такого же компактного
визуального контекста. Вставка trigger words в Studio блокируется при открытом
черновике — пользователь должен сначала Apply/Cancel. Нужен отдельный сценарий
атомарного подтверждения тега и выбранных триггеров, без потери черновика и без
перезаписи чужого изменения prompt. Поддержку negative/других редакторов следует
проверить отдельно, не смешивая её с фактической семантикой negative LoRA в A1111.

**LoRA Block Weight.** В `scripts/lora_block_weight.py` есть XYZ plot,
Effective Block Analyzer, X/Y/Z-параметры, threshold сравнения изображений,
редактор/перезагрузка пресетов и блоковые слайдеры. Наличие `lbw`, `lbwe` и
таблицы покрытия в Studio не заменяет запуск серии сравнений изображений.
Эксперименты — отдельный поздний модуль после приёмки runtime: фиксировать seed,
checkpoint/LoRA hashes, prompt, sampler и фазу Hires; сохранять результаты.
Не переносить старые глобальные monkeypatches без проверки совместимости.

**LoRA Control.** `scripts/loractl.py` и `loractl/lib/plot.py` умеют добавлять
график записанных TE/U-Net множителей по шагам из callback. SVG в Studio показывает
заданное расписание, а не записанный runtime. Нужен отдельный opt-in trace нескольких
LoRA с разделением base/Hires. Это диагностический график множителей, не измерение
силы влияния на изображение и не доказательство изменения TE conditioning на каждом
шаге. Не менять формулы весов ради отображения графика.

**Кривые.** У Studio есть визуализация и редактируемые строки точек; само наличие
SVG не означает интерактивное перемещение точек. Отдельный follow-up: dragging
точек, клавиатурное редактирование, диапазон шагов/фазы, независимость TE/U-Net,
сохранение отрицательных весов и корректный режим наследования.

## План небольших безопасных изменений

1. **Быстрые блоки.** Переиспользовать один компонент в Quick tune/Studio.
   Ползунок и число связаны с одним черновиком; диапазон не обрезает уже введённые
   значения. Пустой/незавершённый ввод не превращается в 0. Неизвестный профиль не
   угадывать по одному названию; оставить явный выбор и диагностику.
2. **История правок.** Отдельный небольшой модуль состояния, не ещё обработчики
   внутри большого View. Одна протяжка слайдера — один шаг Undo; Redo обрезается
   после новой ветки. Черновики различаются по вкладке и occurrence, не только
   по имени LoRA. Закреплённые снимки можно сохранять в существующую библиотеку.
3. **Компактное окно.** Перестроить секции без изменения грамматики тега:
   сверху LoRA/основной вес, рядом краткий выбор пресета; блоки по раскрытию;
   Apply/Cancel доступны без прокрутки содержимого. Перемещение мышью опционально,
   клавиатурная работа и автоматическое вписывание в экран обязательны.
4. **Контекст/кривые**, затем **trace/эксперименты** — отдельные задачи, с
   собственными контрактами и тестами. Не связывать весь UX-релиз с переписыванием
   LoRA runtime или интеграцией идей из других WebUI.

### Инварианты, которые нельзя потерять

- Apply меняет только выбранное вхождение; Cancel/Escape не меняют prompt.
- Повторяющиеся имена, неизвестные аргументы, независимые TE/U-Net/DYN/Hires
  и elemental override сохраняются. История не восстанавливает чужой prompt.
- При внешнем изменении prompt старый черновик не применяется молча.
- txt2img/img2img не делят незавершённые правки. Нельзя иметь два редактора,
  одновременно записывающих один черновик.
- Не копировать автоматическую запись при любом клике вне окна: это теряет
  пользу явного Apply/Cancel. Live preview требует отдельной явной опции.

### Приёмка UX

Проверять реальные действия, а не только число автотестов: открыть тег → изменить
блок → сравнить предыдущий вариант → подтвердить; сохранить/вернуть комбинацию
TE+U-Net+DYN+curve+Hires+lbwe; выбрать триггер при открытом черновике. Проверить
1366×768, 1920×1080 и узкую область ~800 px, светлую/тёмную тему, масштаб 125/150%,
Tab/Shift-Tab/Escape и видимость Apply. Затем повторить в настоящем Gradio с
пользовательской темой. Только после этого называть Studio удобной заменой.

## Что изменено в этой проверке

UI пока не переписан: это аудит и коррекция очередности работ. Отдельно завершено
критическое исправление `modules/sd_vae.py`: после отказа изменяющей модель фазы
VAE reload неполный объект исключается из активной модели/кэша. Исходная ошибка
сохраняется; разрешение имени VAE до начала изменений не удаляет исправную модель.
Новый `test/test_runtime_vae_failures.py`: 3 метода, включая 7 точек отказа.
Общий CPU/AST runtime-набор: **72 PASS**. Это не тест CUDA/генерации.
