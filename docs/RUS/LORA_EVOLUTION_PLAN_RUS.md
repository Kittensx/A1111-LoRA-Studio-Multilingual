## Цель интерфейса

Выбрать LoRA, настроить вес и готовый режим без знания lbw/lbwe.
Точные параметры остаются доступны. Новые режимы подключаются через общие
контракты, а их работа проверяется независимо от интерфейса.

## Этапы и условия завершения

1. **Единый выбор пресетов — реализован первый инкремент; визуальная приёмка ещё не пройдена.**
   - Один каталог для Quick tune и полной Studio: простые режимы, старые
     block/elemental-пресеты, пользовательские снимки настроек.
   - Описание изменяемых параметров до применения; выбор пункта ничего не
     записывает. Кнопка Use preset меняет черновик, Apply — выбранный тег.
   - Общие режимы вычисляются относительно текущих весов; повторное применение
     не должно случайно уменьшать вес снова и снова.
   - Пресеты блоков меняют только блоки, elemental — только module override;
     сохранённый Studio-пресет восстанавливает полный снимок. Эти различия
     видны пользователю. Существующий override остаётся видимым.
   - Явно несовместимые семейства раскладок блокируются. Auto не означает,
     что совместимость с загруженным checkpoint уже проверена.
   - Сохранение доступно рядом с быстрыми настройками; импорт, удаление и
     управление библиотекой остаются в раскрываемом разделе.
   - Проверки: повторяющиеся LoRA, Cancel/Apply, устаревший черновик,
     кривые, пользовательские пресеты, профиль, одновременные представления.

2. **Модули расчёта и адаптеры архитектуры — запланировано.**
   - ArchitectureAdapter описывает известные имена слоёв, компоненты и
     поддерживаемые операции. Сначала классические модели, затем отдельные
     проверенные архитектуры. Название DiT и длина 61 не доказывают поддержку
     произвольной transformer-модели.
   - ControlModule объявляет ID/версию, входные параметры, затрагиваемые
     компоненты и правила сочетания. Начать с имеющихся весов TE/U-Net,
     расписания, Hires, lbw и lbwe.
   - Из проверенных параметров собирается неизменяемый план на одно применение
     LoRA; загруженные tensor payloads остаются отдельно.
   - Порядок вычисления фиксирован: вес компонента и фазы, расписание,
     интервал активности, block mask с elemental override. Последний именно
     заменяет вес блока на совпавших слоях, а не умножается на него повторно.
   - Merge/functional используют один вычислитель и одинаковую cache identity.
     Это проверяется на существующих форматах, включая особые пути DoRA/OFT.
   - Пустой набор дополнительных функций сохраняет обычное поведение.

3. **Настройки через UI без длинных тегов — запланировано.**
   - Видимый режим на конкретном вхождении LoRA; txt2img/img2img независимы.
   - Backend получает версионированный снимок настроек на запрос и сохраняет
     его в metadata генерации. Имя пресета недостаточно: его содержимое
     может измениться после сохранения изображения.
   - До внедрения этого пути действуют существующие теги. Не вводить сейчас
     скрытый глобальный preset, который нельзя восстановить из результата.
   - Отдельный согласованный порядок приоритетов: параметры тега, параметры
     конкретного вхождения, явно включённые пользовательские defaults.
   - Restore, batch, Hires и API обязаны восстанавливать тот же снимок.

4. **Проверка результата и экспериментальные функции — запланировано.**
   - Сравнение обычного пути, старых расширений и новых режимов с одинаковыми
     checkpoint/LoRA/hash, prompt, negative prompt, seed, sampler, steps,
     CFG, разрешением и Hires. Сохранять фактические параметры.
   - Разделять совместимость расчёта, скорость/VRAM и субъективное качество.
     Удачный отдельный кадр не доказывает общего улучшения.
   - Региональное применение и более сложное смешивание — отдельные модули
     после проверки базового пути; им может понадобиться доступ к активациям,
     которого нет у простых множителей весов.

## Как сочетаются TE, U-Net и DYN

`<lora:name:te=0.5:unet=0.8:dyn=16>` задаёт три независимых параметра:
силу для text encoder, силу для U-Net и ограничение ранга в поддерживающих
это LoRA-слоях. DYN не является третьим множителем веса или числом шагов.
В conventional LoRA используются первые rank-компоненты матриц; это не
гарантия качества и не универсальная операция для всех типов адаптеров.
Без `dyn` ранг не ограничивается. UI явно показывает Off / full rank.

- Ключи в теге регистрозависимы: `te`, `unet`, `dyn`, не `TE/UNET/DYN`.
  Неизвестные ключи сохраняются; Studio предупреждает о похожих заглавных.
- Позиционная форма `:0.5:0.8:16` означает TE, U-Net, DYN. Именованные
  аргументы перекрывают соответствующий позиционный аргумент. Без U-Net он
  наследует TE, включая кривую; интерфейс затем редактирует их независимо.
- `hr`, `hrte`, `hrunet` задают отдельные веса Hires. Отсутствующее значение
  в UI означает наследование, а не ноль. DYN остаётся настройкой применения
  LoRA, отдельного Hires DYN в текущем контракте нет.
- `lbw` задаёт веса блоков; `lbwe` заменяет выбранные блочные множители на
  совпавших модулях. Они не стирают TE/U-Net/DYN. Конкретный эффект зависит
  от архитектуры, доступных LoRA-слоёв и содержимого пресета.
- Пустое **обязательное поле редактора** блокирует Apply. Это отличается от
  исторической грамматики пустого значения **в теге**: редактор не должен
  незаметно применять старое значение, пока пользователь ещё вводит новое.
