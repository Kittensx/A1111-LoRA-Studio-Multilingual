### A1. Авторизация маршрутов Studio

`extensions-builtin/Lora/scripts/lora_script.py:140–160`: GET/PUT регистрируются
на `app` напрямую. `modules/api/api.py:274` добавляет `Depends(self.auth)` только
маршрутам, созданным через `Api.add_api_route`. `api_only` создаёт обычный FastAPI,
а setup_middleware добавляет GZip/CORS, не общую Basic-auth защиту.

Проверка использовала настоящий FastAPI TestClient без сетевого listener:
защищённый контрольный маршрут вернул 401; production PUT Studio без credentials
вернул **200** и вызвал подменённое сохранение один раз. Реальный config не писался.
Это не только эстетика интерфейса: сетевой клиент может изменять библиотеку,
несмотря на ожидание защиты API. Для изолированной localhost-установки экспозиция
иная; открытость конкретной установки пользователя в интернет не проверялась.

Решение: единая политика доступа для всех Studio endpoints (presets/coverage/
sidecar/refresh), согласованная с API-only и Gradio-session режимами. Не добавлять
Basic-auth вслепую только к PUT: browser fetch из авторизованного Gradio также
должен продолжать работать без хранения пароля в JS. Тесты: anonymous 401/403,
валидный клиент успешно читает/пишет, неправильные credentials не пишут, режим
без auth сохраняет ожидаемую работу. CORS не заменяет авторизацию.

### A2. Отсутствующий bias путается с отсутствующим backup

`extensions-builtin/Lora/networks.py:540–554`: значение None используется и для
«backup ещё нет», и для «исходный слой не имел bias». Full-адаптер с `diff_b`
создаёт bias при первом merge. Второе применение того же адаптера пытается
заново сохранить этот уже изменённый bias и выбрасывает:
`no backup bias found and current bias are not unchanged`.

Воспроизводитель использует реальный `NetworkModuleFull`, настоящие tensors и
production merge/cache. Это не утверждение, что любая обычная LoRA содержит
output bias: случай относится к адаптерам, которые возвращают `ex_bias`.

Решение: явно различать инициализированный backup с исходным None и отсутствие
backup. Не ограничиваться подавлением исключения. Приёмка: первое/повторное
применение, изменение веса, две LoRA, disable с восстановлением **None**, rollback
после сбоя; затем Conv2d и MHA out-projection. Проверить requires_grad/dtype/device.

### A3. Bias Q/K/V не применяется

`extensions-builtin/Lora/networks.py:601–603,633–635`: второе значение
`calc_updown` присваивается `_`. Production Full-адаптер возвращает ненулевой
`diff_b`, но MHA.in_proj_bias / packed QKV.bias не меняются. Воспроизведено
на двух разных путях с нулевой weight-delta и единичной bias-delta.

Решение: либо полноценно применять и восстанавливать Q/K/V bias в правильной
упаковке, либо явно отвергать неподдерживаемый формат ДО изменения слоя.
Молчаливое игнорирование недопустимо. Если выбран явный отказ, обновить негативный
тест под этот контракт; текущие красные tests ожидают полноценное применение.
Проверить cache identity, исходный None, несколько адаптеров, rollback и FP8.
Нельзя исправить MHA только добавлением in_proj_bias: его backup/restore сейчас
обслуживает out_proj.bias, потребуется согласованное изменение всего жизненного цикла.

### A4. SDXL Embedding: сумма размерностей недостаточна

`modules/textual_inversion/textual_inversion.py:165,300,414`: проверяются
двумерность, float-тип и равное количество векторов, но совместимость с моделью
сводится к сумме ширин. Пара clip_l=1024, clip_g=1024 проходит gate expected=2048.
Затем реальный `EmbeddingsWithFixes` с token embedding шириной 768 падает при
вставке clip_l=1024. Сам TI-файл при этом уже зарегистрирован.

Решение: получать требования каждого encoder от активной модели, проверять
каждую часть до регистрации/переноса на GPU; сообщение должно назвать файл,
encoder, ожидаемую и фактическую размерность. Не хардкодить 768/1280 для любых
будущих архитектур. Тесты: корректная пара, неверное разделение с правильной суммой,
смена checkpoint, classic TI, отсутствующая часть, неправильный rank и vector count.

### A5. Раннее отклонение нечисловых весов TI

`Embedding.validate_sdxl` принимает float-матрицу, содержащую NaN. Новый тест
ожидает диагностический ValueError, но загрузчик возвращает Embedding. Прогон
изображения с NaN не делался: загрязнение conditioning — риск, а не измеренный
в этом аудите результат генерации. Inf отдельно ещё не воспроизведён.

Решение: общая проверка конечности, формы и непустоты векторов для classic/SDXL
до регистрации, с понятной ошибкой вместо молчаливой замены NaN на ноль. Охватить
NaN, ±Inf, пустые/неправильные матрицы и корректные большие значения. Не смешивать
эту проверку с разрешением небезопасного pickle.

## VAE: что подтверждено и чего тесты не обещают

- Прежние тесты семи точек отказа, preflight и success/no-op проходят.
- Новая проверка использует настоящий `.pt` во временной папке на D:, реальный
  `load_state_dict`, production load_vae/_load_vae_dict/reload_vae_weights.
  Корректный weight успевает записаться, затем неверный размер bias вызывает
  исключение. v8 удаляет испорченный объект из active/cache, другой cached model
  сохраняется, loaded_vae_file очищается, ошибочная VAE в кэш не публикуется.
- Это **изоляция повреждённой модели**, не возврат её весов к предыдущему состоянию.
  Сам объект остаётся частично изменённым; сторонние ссылки на него не обезврежены.
  Нужен явный reload checkpoint и понятное сообщение в UI.
- Важное уточнение старых тестов: callback failure там внедрён в подменённый
  dispatcher. Настоящий `modules/script_callbacks.py:270–275` ловит ошибки отдельных
  расширений и только логирует. Поэтому нельзя заявлять, что v8 автоматически
  изолирует модель после любого сбоя произвольного callback расширения.

Следующая приёмка VAE: A → внешняя VAE → None/Automatic → B → cached A;
битый файл/неверная форма, ошибка во время Hires override, восстановление settings
и следующая успешная генерация, fp16/bf16 и реальный low-VRAM. Отдельно проверить
preflight чтения VAE до снятия hijack: сейчас некоторые ошибки обнаруживаются
после начала изменяющей фазы и консервативно выключают модель целиком.

## UI: повторная проверка

Навык computer-use использован для реального браузерного просмотра локального
стенда. Повторно прошли **55 UI checks**, включая светлую/тёмную темы с токенами
и без. Узкая компоновка fixture подтверждает перегруженный popup: Apply/Cancel
ниже исходной видимой области. Стенд ограничивает область приложения, но это
не полноценная проверка всех размеров viewport или мобильного браузера.

Новая находка: после клика Cancel `document.activeElement` — BODY; исходный
prompt сохранён. Escape в коде отдельно возвращает фокус в prompt, кнопка — нет.
Добавить один механизм закрытия с сохранением/возвратом инициатора, проверять
Apply/Cancel/крестик/Escape, переход Full Studio и смену вкладки.

Основные неудобства прежнего UX-аудита сохраняются: блоки без слайдеров глубоко
в Advanced, нет истории вариантов, перегруженный неперемещаемый popup. Также
нужно отдельно принять trigger workflow, preview, клавиатурные действия и кривые.
Базовая Studio привязана к `#<tab>_prompt > label > textarea`; negative/сторонние
редакторы не считать уже поддержанными только из-за наличия right-click.

Ограничения: mock API, отсутствует SourceSansPro CSS (fallback font), Gradio не
запущен. Белые нечитаемые поля на стенде не воспроизведены. Нельзя распространять
это на все пользовательские темы. Старые расширения не активировались.

## Дополнительные границы проверки

- Кэш LoRA/FP8, meta-loader, порядок установки/снятия hooks и cleanup после
  исключений покрыты существующими CPU/AST regressions, не всей backend-матрицей.
- Staged TI save и SHA256-связка optimizer проверяются существующими тестами;
  `.pt`+`.optim` не атомарная пара, concurrent writers/power loss не гарантированы.
- Safe-unpickle не отключался. Инспектор header и установщик проверены тестами.
- Sidecar-код ограничивает размер чтения и соседнюю директорию, presets имеют
  schema/лимит числа элементов. Это полезные ограничения, но не замена auth.
  Гонки файлов/symlink и одновременное сохранение библиотеки ещё не доказаны безопасными.
- PUT Studio вызывает общий Options.save: прямой open('w') всего config. В этом
  проходе сбой записи config не внедрялся. Добавить проверку disk-full/permission/
  двух клиентов и отсутствие ложного «сохранено»; локальная запись в память не
  равна успешному сохранению на диск. Не исправлять только фронтенд-уведомление.
- Не проверены реальные CUDA kernels, расход VRAM/скорость, SD1.5/SDXL изображения,
  качество стиля, обучение TI, внешние квантователи и версии Python/Torch/Gradio.
  SDXL TI training по-прежнему явно не поддерживается. Новая архитектура не нужна
  для закрытия A1–A5 и не должна маскировать эти ошибки.

## Исправленная дорожная карта и условия завершения

   неавторизованную запись, ошибку save, конкурентную библиотеку. Не считать
   v8 безопасным для публикации в сеть только из-за наличия --api-auth.
2. **Правильность адаптеров/Embedding.** A2/A3: явное состояние backup и полный
   bias-контракт; A4/A5: валидация по encoder и конечности до регистрации.
   Каждый дефект сначала красный тест, затем зелёный; весь прежний набор сохраняется.
3. **Восстановление VAE/checkpoint и интеграция.** Описанная выше матрица на
   рабочем Gradio/GPU, реальная LoRA + TI одновременно, Hires/cancel/retry,
   чужие hooks. Не заменять её одними заглушками callback или числом CPU-тестов.
4. **Удобная Studio.** Сначала компактное окно с доступными действиями/возвратом
   фокуса; затем быстрые блоки и history. Общие компоненты Quick/Full Studio,
   один владелец черновика, никакой смены default-весов. Дальше preview/triggers,
   интерактивные кривые и выбранное пользователем размещение интерфейса.
   Независимые UI-улучшения можно делать без ожидания исследований всех backend,
   но не объявлять релиз полностью принятым до интеграционного пункта 3.
5. **Релизная приёмка.** Маленький новый кандидат после исправлений, source↔payload
   hashes, installer/rollback на известном baseline, documented unsupported cases,
   версии среды, тесты пользовательских сценариев. v8/ZIP сохранять неизменными.
6. **Позднее развитие.** Runtime trace, XYZ/Effective Block experiments, адаптеры
   архитектур и идеи других WebUI — отдельные задачи после соответствующих проверок.

Этапы 1–5 — до принятого базового релиза; пункт 6 — расширения после него.
