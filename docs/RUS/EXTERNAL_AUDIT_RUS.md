## Новые пользовательские действия и изменения совместимости

- Settings → Actions: Force reload checkpoint from disk; Force reload selected VAE
  from disk. Обработчики проходят через очередь генерации. Саму Gradio-страницу
  здесь не запускали; код callback и семантика загрузчиков проверены отдельно.
- VAE Automatic теперь не ищет приблизительные имена в произвольной папке.
  Старый выбор неоднозначного basename надо заменить на путь-квалифицированную запись.
- Если выбран None/checkpoint VAE, отдельного внешнего VAE-файла нет; для перечитывания
  базы с диска используйте Force reload checkpoint, а не кнопку внешнего VAE.
- Неизвестный checkpoint без YAML теперь даёт понятный отказ вместо предположения SD1.
  Полнота всех архитектурных fingerprints ещё не доказана.
- Сигнатура файла — не криптохеш содержимого. Файловые системы с неизменными stat
  полями могут скрыть изменение; для такого случая есть явный принудительный reload.
- При параллельном Options.set второй запрос может вернуть accepted до завершения
  общего callback. При успешном callback владелец доводит тот же ключ до актуального значения. Это НЕ
  межпроцессная транзакция и НЕ гарантия порядка callback разных ключей/чужих opts.data writes.

## Проверка установки, а не только папки files

`tools/post_install_smoke.py` создаёт новую копию в <HISTORICAL_AUDIT_ROOT>/tmp
из локальных `Downloads/stable-diffusion-webui-dev.zip` и `source/modules.zip`.
Это доступная локальная расширенная база со старым REGION; её точное совпадение
с архивом в чужом аудите не предполагается. После install копируются ТОЛЬКО тесты,
а не modules из reference/verification-only. Запускаются runtime, parser/API и Node;
затем проверяется побайтовый rollback всех затронутых исходных файлов.

У этой локальной базы 16 UNKNOWN файлов. Override использован только в свежей
тестовой копии, созданной скриптом. На пользовательской установке normal installer
сохраняет запрет UNKNOWN; этот тест не разрешает слепую замену произвольной сборки.

Конкретные результаты финального прогона и SHA256 архива — в VERIFICATION.md
пакета и отдельной квитанции v12. Старые отчёты внутри пакета остаются историей.

## Инструмент из ZIP и его ограничения

Присланный header inspector не загружает tensor payload, но его SDXL_DUAL_OK
не проверяет положительность числа строк, dtype/offsets/конечность tensor values.
Равенство форм не равно валидности файла. В v12 добавлен
`tools/inspect_embedding_header.py`: использует тот же bounded preflight, что runtime,
проверяет положительные размеры и float dtype, не открывает pickle и явно пишет
HEADER_COMPATIBLE_ONLY. Offset/контент проверяет библиотека safetensors при загрузке;
обучающая совместимость с checkpoint из заголовка не доказывается.
