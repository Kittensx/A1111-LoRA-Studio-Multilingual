## Что исправлено

### Один способ определения версии файла для связанных кэшей

Payload LoRA, metadata и hashes используют `modules.asset_files.file_signature`:
resolved path, device, inode, размер, mtime_ns, ctime_ns. Новое поле дискового
кэша — `file_signature_v1`; записи только с mtime не принимаются и лениво
пересчитываются. Массового удаления пользовательского кэша нет.

При same-size replacement с прежним mtime обновляется `NetworkOnDisk`,
пересобирается каталог, удаляются старые alias/hash lookup, обновляется версия
архитектуры и загружаются новые веса. Проверена цепочка реальных функций
`list_available_networks → load_networks → повторная активация`, с явным refresh
и без него, вычислением дельты Torch и повторным использованием неизменного файла.
Проверки до/после чтения и перед активацией отклоняют замеченную подмену файла.
Есть настоящий writer-thread с заменой tempfile между чтением payload и
публикацией результата; декодер тензоров в этом тесте — stdlib fixture.
Исчезновение файла во время refresh не вызывает вторичный `None.filename` crash.

Заявленный `sshs_model_hash` больше не принимается загрузчиком как проверенный
хеш весов. При первой загрузке вычисляется фактический hash; дальше работает кэш.
Это может увеличить первое время загрузки, особенно с сетевого диска. При
`--no-hashing` валидный ранее вычисленный hash допустим, новый не вычисляется;
после смены версии не подставляется старый/заявленный hash. В metadata-панели
Studio поле теперь явно подписано как **Declared hash / unverified**.

Кэш `hashes.py` общий для WebUI: изменение касается не только LoRA, но и его
других потребителей. Проверены normal SHA, addnet SHA, legacy partial hash,
одинаковый title для разных путей, время назад, старые записи и отказ при смене
файла во время чтения. Это не переаудит всех возможных внешних расширений.

### Конкурентные настройки: явный отказ вместо преждевременного успеха

Пока callback ключа выполняется, повторный `Options.set` того же ключа вызывает
понятный RuntimeError с предложением повторить запрос. Это касается и того же
значения, и `run_callbacks=False`. Успех возвращается только после завершения
callback. При его исключении значение откатывается; сохранение config и
`set_and_save` не допускают запись промежуточного состояния при активном callback.
Глобальный config_lock **не удерживается** во время callback и ожидания очереди.

`POST /sdapi/v1/options` возвращает HTTP 409 при этом конфликте или отказе callback,
а не ложный успешный ответ. Проверен настоящий метод API с временным config:
конфликт/ошибка не сохраняются, повтор после завершения успешно записывается.

**Изменение контракта:** конкурентный вызывающий код должен обработать отказ и
повторить действие, а не рассчитывать на автоматическое объединение запросов.
Это не транзакция всего batch настроек: ранее успешно изменённые другие ключи
могут остаться изменёнными при отказе следующего. Прямые записи `opts.data`,
присваивания атрибутов в обход `set`, callbacks иных ключей и произвольные
побочные эффекты расширений не получают общей транзакционной гарантии.
Откат значения не способен сам по себе отменить любой уже выполненный GPU-эффект.

### Честные подписи Studio

Заголовки различают `TE at text encoding (first point)` и `U-Net per sampling step`.
Coverage назван `File-key coverage (not runtime application)`; уже существующее
предупреждение об отсутствии проверки checkpoint сохранено. Стабильные имена
полей для accessibility/автоматизации сохранены. Полноценный runtime coverage
не добавлялся. Это уточнение интерфейса, не новый алгоритм генерации.

обновляются push-событием: для уже открытого UI требуется обычный refresh.
