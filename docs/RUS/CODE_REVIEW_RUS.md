# A1111 LoRA Studio Pack v15 — обзор кода и оценка переноса в ImageGen

## Что это за пакет

Это **набор модификаций A1111 WebUI**, а не один LoRA-файл или самостоятельная программа. Он изменяет встроенное LoRA-расширение и несколько модулей ядра A1111, добавляет редактор Studio, парсер тегов, изменения загрузки и выполнения, API-функции и автономный установщик с проверкой хешей, резервированием и откатом.

Для пользователя доступны отдельные веса TE/U-Net, кривые по шагам, Start/Stop, Hires.fix, динамический ранг, блочные таблицы 12/17/20/26/61, переопределения модулей `lbwe`, несколько независимых вхождений одной LoRA, визуальные редакторы и пресеты, диагностика metadata/sidecar. Изменения остаются в черновике до Apply.

## Основные файлы

- `javascript/loraStudioModel.js` — браузерный разбор/сериализация тегов и безопасная замена выбранного участка.
- `javascript/loraStudioView.js` — интерфейс txt2img/img2img и черновики.
- `javascript/loraStudioPresets.js`, `loraStudioCurves.js`, `loraStudioBlocks.js` — пресеты, кривые, маски.
- `extensions-builtin/Lora/lora_schema.py` — контракт и проверка данных.
- `lora_runtime.py`, `lora_advanced.py`, `network.py`, `networks.py` — применение весов, кеширование и жизненный цикл.
- `modules/processing.py`, `sd_models.py`, `sd_vae.py`, `textual_inversion.py` — глубоко привязанная к A1111 логика.
- `install.py`, `manifest.json`, `patches/processing-hires.json` — проверяемые операции установки/отката.

## Перенос в ImageGen

**Возможен, но не в виде установки исходного ZIP.** Код зависит от Gradio, структуры `modules.*`, глобального `opts`, идентификаторов текстовых полей A1111 и собственных runtime-хуков. Установщик специально проверяет, что целевая папка — A1111.

Предлагается выделить независимое `LoRA Studio Core`: типизированную спецификацию, парсер, сериализатор, версионированные пресеты, обработку кривых и таблиц; затем написать `ImageGen LoRA Adapter` для существующих бэкендов, семейства модели, состояния рабочего пространства и GPU-планировщика ImageGen. UI адаптировать к существующей архитектуре ImageGen, не перенося чужую привязку к Gradio.

Порядок: аудит происхождения/лицензий и API ImageGen; тестовые JSON-контракты; новый UI с черновиком и точным Apply; реализация для одной проверенной модели; затем SDXL/SD3.5 и другие семейства только после реальных тестов; проверка повторных LoRA, масок, Hires и VRAM. Надпись Flux в metadata не гарантирует поддержку генерации Flux.

## Проверки и ограничения

Исходный README v15 сообщает о 142 CPU runtime-проверках, 64 проверках parser/API/config и 13 подтестах, 22 Node-тестах и 62 UI-проверках, а также откате установки. Это **отчёт автора исходного пакета**, а не проверка с реальным GPU/Gradio. Пользовательские safetensors и производственная готовность не подтверждены.

В мультиязычном ответвлении повторно проверены установщик, Node DOM и локализационные тесты. Python inference не изменён, но браузерный интерфейс, CSS и manifest отличаются — перед применением необходима проверка в живом браузере.

## Многоязычность

Добавлены отдельный `loraStudioI18n.js` и каталоги языков: английский, русский, французский, испанский, итальянский, японский, упрощённый китайский, бразильский португальский, немецкий и корейский. Выбор языка хранится в `localStorage`, одинаков для txt2img/img2img. Промпты, теги, имена моделей и числовые значения остаются без изменений. Если перевода нет, используется английский.

**Охват пока неполный:** переведены 67 ключевых строк на язык из 142 статических ключей первоначального списка. Длинные подсказки, переменные сообщения, backend-ошибки и общий UI A1111 переведены не полностью. Подробности в `I18N_GUIDE_RUS.md`.
