# LoRA Studio v11: сочетания, исходные расширения и границы проверки

Дата: 2026-11-11. Это отчёт о конкретном исправлении, а не объявление всего плана завершённым.
Рабочий проект: `<A1111_SOURCE>`.
Резервная копия перед этим проходом: `<HISTORICAL_AUDIT_ROOT>/before-20261110-combinations`.

## Что было действительно неправильно

1. Явный постоянный Hires-вес не отключал основную кривую. Теперь `hrunet=0.3`
   заменяет `unet=0.5@5,1@9` во втором проходе; `hrte` действует независимо.
2. TE-кривая зависела от оставшегося глобального номера шага. Теперь берётся её
   первая точка: полноценный пересчёт текста на каждом шаге НЕ реализован.
3. Некоторые SDXL OpenCLIP-ключи с индексом encoder, например
   `1_model_token_embedding`, ошибочно считались U-Net и получали его вес/тайминг.
4. Известные блоки, пропущенные в короткой классической LBW-таблице, получали 1
   вместо 0. Сверено с `to26()` оригинального Block Weight. Неизвестные ключи
   сохраняют fallback 1. Это намеренно меняет результат относительно v10.
5. Classic middle-block transformer мог ошибочно определяться как flat DiT,
   и элементные правила IN05–OUT05 не попадали в нужный MID attention.
6. Смешанные единицы `start=5:stop=0.8` сравнивались как обычные числа.
   Теперь сравниваются разрешённые границы; отрицательные границы запрещены,
   shorthand не теряет минус и понимает scientific notation.
7. DYN игнорировался для CP-разложения. Теперь обрезаются up/down/mid,
   исходный alpha/rank scale сохраняется. Это не обещание DYN для всех LyCORIS.
8. Профиль блоков отсутствовал в conditioning signature; теперь включён.
9. UI показывал встроенную таблицу, даже если пользователь переопределил MIDD.
   Теперь отображается именно пользовательская таблица; ошибочное переопределение
   не подменяется молча встроенным.
10. Конвертация короткой маски в визуальную classic-таблицу работала неудобно.
    Теперь сопоставление по ID, отсутствующие блоки — нули. Если конвертация
    потеряла бы ненулевые блоки, она не выполняется молча.
11. Для абсолютных шагов кнопка добавления точки кривой была недоступна.
    Теперь между 5 и 9 можно добавить интерполированную точку 7.
12. Узкая Studio внутри широкого окна оставалась двухколоночной. Добавлен
    container query по ширине самой Studio; media-query fallback сохранён.

## Что взято при повторном сравнении трёх исходников

- `extensions/check/sd-webui-loractl`: сопоставлены единицы кривых, интерполяция,
  Hires override и проблема параметров, привязанных только к имени LoRA.
  У нас настройки остаются отдельными для каждого вхождения одного файла.
- `extensions/check/sd-webui-lora-block-weight`: сверены BLOCKIDS, таблицы
  MIDD/ALL, нулевое расширение коротких масок и приоритет elemental override.
- `extensions/check/sd-webui-weight-helper-main`: взяты принципы ползунок + точное
  значение, расширяемый диапазон, соответствие блоков и явный выбор layout.

В UI добавлены отдельные ползунки блоков рядом с точным вводом; число 3.5
расширяет диапазон, а не обрезается до 2. Сохраняются групповые операции.
Неизвестный LBW/LBWE preset и неполная числовая таблица блокируют Apply.
Пустой ввод не превращается в ноль или скрытое предыдущее значение.
Правила LBWE окончательно валидируются backend, не только браузером.
Исходные три расширения не изменены. Это не полный перенос всех их функций.

## Однозначная семантика сочетаний

- Без дополнительных аргументов простая LoRA не получает скрытый preset.
- TE и U-Net независимы. DYN — ограничение rank поддерживаемого слоя, не сила.
- LBW умножает вклад выбранного блока; совпавший LBWE заменяет именно блочный
  множитель, затем по-прежнему действуют TE/U-Net и U-Net start/stop.
- `MIDD` — многоблочный legacy preset, не синоним единственного M00.
- `ALL` с 17 значениями не равен всем 26 блокам: пропущенные известные блоки — 0.
  Чтобы снять маску целиком, используйте режим All blocks / no module overrides.
- `0.5@5,1@9`: до шага 5 — 0.5, между 5 и 9 — линейная интерполяция,
  начиная с 9 — 1. Кривая сама по себе НЕ выключает LoRA снаружи этого интервала.
- Если все позиции кривой находятся в 0..1, это доли прохода; иначе все позиции
  трактуются как абсолютные шаги. Нельзя смешивать единицы точек внутри кривой.
- Start/Stop: 0..1 включительно — доля диапазона 0..N-1; 1 означает конец,
  значения >1 — абсолютные zero-based шаги. Границы включительные. Это не точная
  копия старого LBW, где 1 и округление границ могли означать другое.
- Start/Stop ограничивают U-Net, не уже рассчитанный TE conditioning.
- Для TE используется первое значение кривой. Кривые отдельных блоков,
  полноценные динамические TE conditioning и автоматический выбор профиля
  архитектуры в этом этапе не добавлены.

## Проверено

- 112 runtime-тестов с существующим Torch CPU, production definitions через AST.
- Новая матрица: 1/2/4 вхождения, повтор одного payload, base/Hires, 5 видов
  ключей, 11 шагов = 330 сценариев timestep/layer. Независимая арифметика ожидаемых
  delta, merge/repeated merge, functional forward, обратный порядок, disable,
  неизменность исходных факторов. Тест с embedding-именем использует Linear;
  реальные Embedding/TI отдельно покрыты прежними runtime-тестами.
- CP DYN проверен отдельно на настоящем Conv2d. Нет реального safetensors loader
  во всей новой матрице: факторы маленькие синтетические.
- 59 parser/API/config тестов + 13 subtests; 22 Node-теста, включая 61 UI assertion.
- 66 UI assertions в браузере: события, два вхождения одного имени, четыре LoRA,
  пустые/ошибочные поля, пресеты, кривые, ползунки, узкая колонка и контраст полей
  в светлой/тёмной теме с/без theme tokens. Использован изолированный fixture,
  сетевые ответы пресетов там подменены; это НЕ полный Gradio.

Ничего не скачано/не установлено. Torch запущен из существующей среды на D:.
Известные предупреждения: нет NumPy в Torch-venv; pytest base_url отсутствует
при отключённых сторонних plugins. Тесты завершились успешно.

## Что осталось в плане — и не объявляется исправным без проверки

1. Интеграционная приёмка в настоящем WebUI: SDXL/WAI, пользовательские LoRA,
   Embeddings, VAE switch, Hires, img2img, batch, отмена/повтор, внешние hooks.
   Нет локального полного Gradio/CUDA окружения с нужной моделью; новые зависимости
   не установлены. CPU-матрица задаёт шаги вручную, не проверяет sampler lifecycle.
2. A/B по фиксированным seed/prompt/model hashes относительно трёх расширений:
   UI-проверки и арифметика не доказывают более красивый стиль или скорость.
3. История/undo черновика, дальнейшее упрощение длинных подсказок/навигации и
   проверка настоящих сторонних тем. Не выдавать ползунки за завершённый UX-план.
4. Новые адаптеры, отдельные per-block curves, динамический TE и расширенные
   XYZ/plot функции — отдельные будущие изменения после интеграционной приёмки.

## Какие файлы изменены относительно v10

Runtime: `extensions-builtin/Lora/network.py`, `network_lora.py`, `networks.py`,
`lora_advanced.py`. Вне builtin: `javascript/loraStudioModel.js`,
`loraStudioCurves.js`, `loraStudioBlocks.js`, `loraStudioView.js`, `style.css`.
Тесты: новые `test_runtime_combinations.py`, `test_lora_interaction_contract.py`,
`lora_interactions.test.cjs`, дополнен `lora_studio_fixture.js`.
Документация: `LORA_EVOLUTION_PLAN.md`, `RUNTIME_STABILITY_FIXES.md`.
В этом проходе `modules/*`, `lyco_helpers.py`, модели и настройки пользователя
не переписывались. Пакет v11 включает предыдущие исправления modules из v10.

Установка только полным комплектом после остановки WebUI; сначала verify/check.
На удалённый `/content/A1111` ничего автоматически не установлено.
