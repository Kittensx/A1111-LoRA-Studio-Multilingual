Package verification found an old test copy of processing.py; the packager was
fixed and the complete runtime suite rerun from the package: PASS. Harness
errors introduced by new dependencies were fixed by extending the real
DB/transaction API, not by deleting assertions. Original external reproducers
from before adaptation were retained in backup.

Final review found a lock-inversion risk in the initial `Options.set`
implementation: a model/VAE-switch callback waits for the generation queue,
while generation may change settings. Fixed: the config lock protects value
updates but is not held while executing a callback. A cross-thread test was
added and passes. If a callback fails, rollback also does not overwrite a newer,
different value.

## Installation on Colab

Stop WebUI, extract v10 outside `/content/A1111`, and enter the package directory:

```bash
python install.py verify
python install.py check /content/A1111
python install.py install /content/A1111
```

Stop and compare the file if UNKNOWN entries or context mismatches are reported.
Do not recommend unconditional `--allow-unrecognized`: complete replacements
may overwrite someone else's changes. processing.py is modified surgically
with six hunks, without replacing the large parser/REGION code. The installer
creates a backup and prints a rollback command. A full Python/WebUI restart is
then required. Local fixes do not reach Colab automatically.

## What is not claimed to be resolved

- Real generation on WAI-Illustrious-17 with user LoRAs and TI, refiner/Hires,
  GPU/FP8/low-VRAM, and Gradio/proxy authentication still need integration runs.
- UI U1/history/more convenient block sliders are a separate UX plan, not part
  of this series of fixes.
- Concurrent whole-library PUT remains last-writer-wins; there is no ETag or
  conflict UI. Direct changes to opts.data and external processes are not
  protected by the process-local lock.
- A1111 intentionally catches errors from third-party model_loaded callbacks;
  these changes do not promise full transactionality for arbitrary extensions.
- Other previously noted lint issues in modules are not among these 11 fixes.

v8 and v9 were not repackaged or deleted. Their SHA256 hashes were rechecked
against previous receipts. The final v10 SHA256 is published after ZIP creation.
